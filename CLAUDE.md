# TermDeck — контекст проекта для ИИ-агента

Ты — senior-разработчик десктопных приложений. Мы создаём кроссплатформенный
SSH/SFTP-клиент, похожий на MobaXterm (рабочее название: "TermDeck").

Этот файл читается всегда. Подробности: `docs/PLAN.md` (план и архитектура),
`docs/UI-SPEC.md` (спецификация интерфейса), `docs/prompts/` (задачи по этапам),
`docs/PROGRESS.md` (текущий статус).

## Стек (не менять без согласования со мной)

- Electron + electron-vite, TypeScript (strict), React 18, Zustand, Tailwind CSS
- @xterm/xterm (+ addon-fit, addon-webgl, addon-search, addon-web-links, addon-unicode11)
- ssh2 для SSH/SFTP/туннелей; @homebridge/node-pty-prebuilt-multiarch для локального shell
- electron-store для настроек, Electron safeStorage для секретов
- zod для валидации IPC, Vitest для тестов, ESLint + Prettier
- lucide-react (иконки), @fontsource/ibm-plex-sans и @fontsource/jetbrains-mono (шрифты)

## Архитектура

- `src/main` (Node: сеть, ФС, процессы), `src/preload` (contextBridge),
  `src/renderer` (React, БЕЗ доступа к Node), `src/shared` (типы, имена каналов, zod-схемы).
- BrowserWindow: `contextIsolation=true`, `nodeIntegration=false`, `sandbox=true`.
- Renderer общается с main ТОЛЬКО через узкое типизированное API из preload.
  Каждый IPC-канал описан в `shared/ipc-contract.ts` (запрос, ответ, события).
  Входные данные в main валидируются zod.
- Одно SSH-соединение на сессию; shell-каналы, SFTP и туннели — каналы поверх него.
- Данные терминала батчатся (8–16 мс) и имеют backpressure.
- Секреты (пароли, passphrase) никогда не сохраняются в открытом виде и не логируются.
- Состояние UI хранится **на вкладку** (путь SFTP, выбор файлов, очередь передач,
  раскладка сплитов), а не глобально.

## UI-эталон

- Визуальный и структурный эталон: `docs/prototype/termdeck-prototype.html`.
  Перед любой UI-задачей прочитай этот файл и `docs/UI-SPEC.md`. Раскладка, пропорции,
  состояния и тексты берутся оттуда. Если нужно отступить от прототипа, скажи об этом
  явно и объясни почему.
- Прототип — статичный макет на ванильном JS. Не копируй его код: переноси дизайн в
  React-компоненты с типизацией, Zustand и Tailwind.
- Цвета, шрифты и размеры не хардкодятся в компонентах. Только дизайн-токены
  (CSS-переменные + Tailwind theme) из `src/renderer/styles/tokens.css`.
- Шрифты бандлятся локально. Никаких запросов к Google Fonts и другим удалённым
  ресурсам: приложение работает офлайн, CSP не допускает remote-контент.
- Иконки: lucide-react вместо эмодзи из прототипа.
- Тексты интерфейса на русском, sentence case, без восклицательных знаков.
  Строки живут в `src/renderer/i18n/ru.ts`.

## Правила работы

1. Работай маленькими шагами. После каждого шага запускай typecheck, lint и build
   и исправляй ошибки, прежде чем идти дальше.
2. Не выдумывай API библиотек. Если не уверен в сигнатуре, прочитай типы в
   `node_modules` или документацию, а не угадывай.
3. Перед написанием кода кратко опиши план: какие файлы создаёшь/меняешь и почему.
4. Не добавляй зависимости без необходимости; перечисляй новые и объясняй зачем.
5. Весь код на TypeScript без `any` (кроме явно обоснованных случаев). Комментарии
   в коде — на английском, только где логика неочевидна.
6. Ошибки сети/ФС обрабатываются явно и показываются пользователю понятным
   сообщением; приложение не должно падать из-за ошибки соединения.
7. Все ресурсы (каналы, потоки, таймеры, listeners) освобождаются при закрытии вкладки,
   сессии и окна. Проверяй утечки.
8. Не меняй код, не относящийся к текущей задаче. Если видишь проблему в другом месте,
   сообщи о ней отдельно.
9. В конце каждой задачи выведи: что сделано, как проверить вручную, что осталось.
   Обнови `docs/PROGRESS.md`.
10. Делай один этап за раз. Не начинай следующий без моего «принято».
